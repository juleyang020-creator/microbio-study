## 🔴 1. 部分条目的图片主题不对应

**证据：**

- `js/view.js:58`：`sars2-rtqpcr` 映射到 `img/test-maldi.svg`；后者 `img/test-maldi.svg:10` 的图题为“MALDI-TOF MS 质谱鉴定”。
- `js/view.js:54`、`:55`、`:56`：三个病毒血清学条目映射到 G 试验图；`img/test-bdg.svg:10` 明确以 G 试验为主题。
- `js/view.js:49`、`:50`：其他方法条目复用 mCIM 专用图，需逐项复核适用范围。
- 真实浏览器打开 `#/tests/sars2-rtqpcr`，实际加载的是质谱图，外部说明仍为“试验示意图”。

**影响：**学习者容易把当前条目与另一项技术的器械、图形和概念建立错误联系。图形精致不能抵消主题错配。

**建议：**先撤下明确不对应的映射；共用图必须确实表达共享概念，并说明适用范围。需要独立图时，只绘制当前条目必要的概念关系。允许暂时无图，同时调整“每个试验必须有图”的测试约束，避免为凑齐覆盖率继续借错图。

**验收：**页面标题、图题和图注对应同一主题；专用图映射增加少量主题断言。现有 `tests/data-integrity.test.js:193` 主要核对文件存在，不能代替主题核对。

**既有检查的漏检原因：**`tools/lint-svg.mjs:74` 到 `:93` 遇到含 `tspan` 的 `text` 时，只检查 `tspan` 内的文字，遗漏父节点自身及 `tspan` 后的文字。例如上述最长尾注只检查到加粗的开头。共有 179 个此类混排文本，分布在 144 张图中。此外，`tools/lint-svg.mjs:73` 未读取祖先字号和锚点，直接以默认值估算；旋转、缩放文本也有跳过检查的分支。

**建议：**长说明换行、增加图高，或移到图下可重排正文；不再靠压小字号塞入固定宽度。保留快速 lint，补齐混排及继承处理，再以浏览器实际文字边界做复核。

**验收：**全部文字在画布内且保留合理留白；在不同系统字体下复查边缘文字。修复混排检查后，应能检出当前已确认的严重案例。

## 🟡 3. 手机上的图内文字明显过小

**证据：**

- `img/biochem-tsi.svg:1` 采用宽 480 的画布，图中大量文字为 9.5。
- `css/styles.css:263` 将主图设置为容器宽度的 100%，最大 520 像素。
- 390 × 844 视口中，TSI 图外框宽 358、内容宽约 356 像素。9.5 字号缩放后约为 **7.05 CSS 像素**。
- 点击放大并自动旋转后，同一图最小文字约 **9.47 CSS 像素**；确有变大，但仍缺少继续放大查看细节的控件。
- 这不是某张图特有：164 张全部包含 9.5 小字；`img/morphology-fungi.svg:27`、`:41`、`:48` 等也将其用于核心说明。

**建议：**

1. 图内保留核心对象、少量标签和必要对照；长解释、例外和来源移到图下正文。
2. 将图中关键标签在正常手机显示时约 12–14 CSS 像素作为设计目标，不作为本次声称的法定或 WCAG 字号门槛。
3. 对信息密集图拆成两个主题，或采用纵向分块；不能只把字体统一放大，否则会产生新的重叠。
4. 放大查看提供适合屏幕、继续放大和复位；旋转由读者选择。

**验收：**390 像素宽页面无需先放大就能辨认核心对照；详细说明用普通网页文字阅读。以实际显示字号与截图验收，不只检查 SVG 源码里的字号。

## 🟡 4. 放大后自动旋转在竖屏平板上裁切图片

**证据：**

- `js/app/detail.js:23` 到 `:26` 对满足宽高比条件的图，在竖屏中自动旋转。
- `css/styles.css:249` 到 `:251` 使用 `height:92vw`，同时取消最大宽高限制，没有再检查旋转后的另一边能否放入屏幕。
- 实测 768 × 1024 视口中的革兰染色图，旋转后边界为：
  - 左上角约 `(30.7, -53.2)`；
  - 宽约 706.5、高约 1130.5；
  - 下边界约 1077.2。
- 图片上下各有约 53 像素超出视口；截图可直接观察到裁切。

**建议：**同时按视口宽、高及图的宽高比计算容纳尺寸。自动适配时首先保证整图可见，再允许手动缩放、拖动和旋转。

**验收：**至少覆盖手机竖屏、手机横屏及 768 × 1024 平板；首次打开完整展示图片，关闭按钮始终可用。

## 🟡 5. 部分文字配色偏淡

**证据：**

| 元素 | 前景／背景 | 计算对比度 |
|---|---|---:|
| 131 张页眉胶囊文字 | #6b7684／#eef1f5 | 4.074:1 |
| 另 1 张同类页眉 | #6b7684／#eef2f7 | 4.106:1 |
| `img/biochem-assimilation.svg:28` 圆中灰字，背景见 `img/biochem-assimilation.svg:27` | #8c96a2／#f7f8f9 | 2.822:1 |
| `img/biochem-gelatin.svg:44` 浅绿框中文字，背景见 `:42` | #2f8f83／#e8f3ef | 3.440:1 |

页眉例子见 `img/genetics-hgt.svg:13`、`:14`。这些小字低于普通阅读文字 4.5:1 的 AA 对比度目标；本轮并非整站 WCAG 合规认证。[W3C SC 1.4.3 官方说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

**建议：**文字使用更深的中性色，保留标本、染色结果与反应本身有含义的颜色。现有正文灰 `#5c6672` 与 `#eef1f5` 搭配可达约 5.15:1。不要给整张图套滤镜或统一改色，以免改变色彩表达。

**验收：**关键标签的文字对比充分；用于区别结果的颜色同时有文字、符号或位置提示。

## 🟡 6. 部分详情页的图注和替代文字过于笼统

**证据：**`js/app/router.js:37` 及 `:53` 到 `:60` 按模块生成统一名称；`js/app/detail.js:400`、`:401` 同时将它用作图片替代文字和图注。实测某专用图的替代文字仅为“试验示意图”。

虽然每张 SVG 内部均有 `title` 和 `desc`，当前外部 `img` 展示链路没有把这些具体内容连接到页面说明。

**建议：**图片元数据至少包含文件、具体图名、简短说明及适用范围。长图说明用可见的图下文字承接；共用图片明确说明与当前条目的关系。复杂图应提供足以表达关键信息的文字描述，而不只报一个笼统名称。[W3C 复杂图片说明](https://www.w3.org/WAI/tutorials/images/complex/)

**验收：**单独读图注能知道图在解释什么；替代文字与当前条目相符。本轮未用 VoiceOver 做完整读屏验证，不将此结果扩大为所有辅助技术的实测结论。

## 🟡 7. 放大弹窗的键盘焦点会进入背景

**证据：**

- `js/app/helpers.js:588` 到 `:596` 已支持用 Enter、Space 激活图片。
- `js/app/detail.js:31` 到 `:41` 打开弹窗后没有转移焦点、限制 Tab 或声明模态状态。
- `js/app/detail.js:9` 到 `:14` 关闭时没有恢复焦点。
- 独立真实 Chromium 实测：焦点在图片上按 Enter 后仍留在背景图片；再按 Tab 跳到背景正文的 PCR 链接；Escape 可关闭，但焦点未回到触发图。

**建议：**打开后聚焦关闭按钮，打开期间使背景不可交互，关闭后回到原触发图；保留 Escape 关闭。

**验收：**仅用键盘即可进入、阅读和退出放大图，弹窗打开时 Tab 不进入背景内容。

## 🟢 8. 视觉系统已有基础，可按图的用途进一步分工

目前统一白底、圆角、线条和字体，格式完整、文件体积小。培养基、生化和形态图已有明确的比较意识，值得保留。

主要版式改进是减少一张图承担的任务：

| 图片类别 | 下一版重点 | 当前审查样本 |
|---|---|---|
| 生化或试验比较图 | 放大核心结果对照；解释放图下，减少上下重复总结 | `img/biochem-tsi.svg:9`、`img/biochem-assimilation.svg:1` |
| 形态图 | 同类对象保持可比较的比例和视角；结构标记靠近对应对象；明确“示意” | `img/morphology-overview.svg:1`、`img/morphology-fungi.svg:1` |
| 机制图 | 突出一个主过程，图中编号对应简短说明；避免在同一画布增加更多支线 | `img/mechanism-protein.svg:1` |
| 培养基图 | 主图突出视觉差异，图例清楚；外观学习配已有真实图谱照片与来源 | `img/media-blood-agar.svg:1`、`img/media-chromagar-candida.svg:1` |
| 模块总览 | 用少量概念帮助选择入口；条目数量和长清单尽量由网页实时呈现 | `img/landing-biochem.svg:1`、`img/landing-glossary.svg:1` |

表中为信息设计建议，不构成图内医学结论的更正。形态与颜色示意适合帮助记忆，真实外观辨识仍应结合已注明来源的图谱。

文件大小优化优先级低：全部 SVG 合计约 1 MB，单张中位数约 6 KB。没必要为了少量压缩收益损失可维护源码、标题和描述，也不建议整体改成位图。

## 建议实施顺序

1. **第一批：修正已确认缺陷。**处理错配映射、8 张边界问题、平板放大裁切，并补上能抓住这些问题的检查。
2. **第二批：提高阅读体验。**修复弹窗焦点、具体图注及浅色小字；选择一张密集图试行“核心图＋图下说明”。
3. **第三批：分类型迭代。**按生化、形态、机制、培养基、总览建立几种版式，再逐批迁移；不必一次重画全部 164 张。

实施时继续遵守现有离线架构。修改应用或图像资源后，更新缓存版本、同步 SVG 预缓存清单并执行发布验证。医学文字和数值若需要改动，另行回源确认。
