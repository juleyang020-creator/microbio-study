# SVG 全量审查与改进建议

日期：2026-09-07。对象：知微静态版当前工作树 `img/` 的全部 SVG。

## 一、结论

**不建议把整套图推倒重画。应先修知识对应、遮挡和裁切，再把“缩小的课件”改成适合手机阅读的教学图。**

现有图的长处是真正的矢量图、统一的视觉风格、清楚的类别组织和较小的体积。主要短板不是缺少装饰，而是：同一张图承担了太多解释任务；部分图片与挂载条目不是同一主题；现有检查主要验证“文件存在、文字估算不越界”，不能证明“内容真正看得见、学习者不会看错”。

本轮整理为 **4 类🔴优先处理问题、5 类🟡阅读与维护问题，以及分类型设计建议**。分级指问题类别，不是有问题图片的数量；同一张图可能同时命中多类问题。

### 范围与可信度

- 审查对象是实际应用引用的 `img/`，不将隐藏目录内旧 worktree 的同名图片混入统计。
- 全部 164 张经过 XML 解析、源文本提取和渲染；全部 4,117 个 `<text>` 在本机 Chromium 中测量实际边界。
- 图片映射按当前运行逻辑核对：8 组映射、310 个键值对，另有 15 个模块总览挂载；全部 164 张均被引用，未发现缺失文件或孤立 SVG。
- 对全部图实测 390×844 手机、768×1024 平板的放大弹窗；详情页另测 320、390、768、1280 宽及浅/深色主题。
- 14 张视觉联系表覆盖全部图片，用于整体布局粗筛；5 张含透明背景的图在白底合成后另外单图复看，结构遮挡等重点图另作放大检查。确定性结论以源代码、浏览器边界及必要的像素比对为依据。这不等于每张图均经过同等深度的逐元素视觉审查，也不等于人工医学专家逐字审核。
- **未逐条回源核验全部医学陈述、实验条件和判读数值。**本文指出的图文主题错误、内部矛盾可直接复现；专业表述的最终更正仍需另行回查教材或现行标准。
- 仅新增审查材料，未修改 SVG、应用代码、医学数据、版本号，也未提交或发布；已有未提交报告及其他任务改动保留。

## 二、🔴 优先处理

### R1. 图与当前条目的主题不对应

**定位与证据：**

| 条目或映射 | 当前图 | 问题 |
|---|---|---|
| `js/view.js:58` 新冠病毒核酸检测 | `img/test-maldi.svg:10` | 核酸检测页面展示的是质谱鉴定图；“都有曲线”不是共用示意图的理由。 |
| `js/view.js:54`～`:56` 病毒血清学条目 | `img/test-bdg.svg:10` | 挂载的是 G 试验专用图，不是相应条目的通用免疫检测概念图。 |
| `js/view.js:94` 钙荧光白染色 | `img/stain-lpcb.svg:2` | 挂的是乳酸酚棉蓝专用图；图题和观察呈现不能代表前者。 |
| `js/view.js:233` 生物膜术语 | `img/glossary-structure-bacteria.svg:2` | 细菌结构图中没有对应的生物膜主体画面，不能只靠大类接近就挂图。 |

**为什么重要：**图片比正文更容易形成记忆。错误的主题关联会使读者记住不相干的器械、读数形状或观察方式，属于学习内容风险，不是普通的装饰问题。

**建议：**

1. 明确不对应的图先撤下，允许暂时无图，不能为了覆盖率借错图。
2. 共用图注明“这是某一大类的概念示意”，并在图上有当前条目所对应的对象；没有覆盖就不挂。
3. `tests/data-integrity.test.js:193` 附近的“每个试验均有图片”测试，改为“已挂图片必须主题匹配”；为已知容易混用的主题增加回归断言。
4. 对 `js/view.js:33`～`:35` 的宽泛机制回退、`:49`～`:50` 的方法复用同样进行逐条语义复核。不能把所有“同类相关”都算作准确配图。

**验收：**页面标题、具体图名、图注三者对应；共用图的适用范围明确。不要用“文件存在”代替这一检查。

### R2. 图层把结构盖住，另有真实的文字相撞

**最严重实例：**`img/glossary-structure-bacteria.svg:53`～`:60` 画了胞内结构与标签；`:96` 后绘制的、不透明的底部说明框覆盖了这一带。

这不是简单的文字包围盒误报。本轮在浏览器副本中删除这一区域的 **8 个图形/文字元素**，前后整图像素完全一致——它们原本就被盖住了。应用源码和原图均未改动。

同一图被 11 个术语条目共用（映射见 `js/view.js:226`～`:236`），其中包括正在被遮住的结构所对应的词条。由此造成“有配图，但关键对象看不到”。

**其他已核实的版式冲突：**

- `img/glossary-structure-fungi-virus.svg:56`、`:60`、`:96`：左右栏标签相互侵入；`:68` 与 `:71` 的两组标签处于同一行并相撞。原图视觉及文字墨迹交集都支持该结论。
- `img/biochem-esculin-starch.svg:18`、`:36`：两栏的长说明在同一基线交叠。
- `img/media-corn-rice-tween.svg:33` 与 `:45`～`:47`：左图注进入右侧卡片；需要同时处理跨栏和后绘制背景覆盖，不能只调整文字颜色。

**建议：**先给主图区、标签区、页脚建立互不侵占的版式边界；不够放时拆图或增加图高，不再缩字。细菌结构图宜分成“细胞壁对照”和“附属/胞内结构”，真菌与病毒总览也适合分开。

**验收：**对应词条的核心对象在最终画面真实可见；不仅检查 `<text>`，还要检查后绘制的不透明背景和结构遮挡。

> 本轮浏览器包围盒初筛有 28 张、49 对潜在文字交叠；其中一些只是字体行框相交，并不是字形相撞。进一步隔离字形得到 12 张、18 对墨迹交集，但这仍包含被遮挡的底层文字，**不能直接宣传为“12 张可见重叠”**。具体定案采用上面的逐项证据。

### R4. 图中有与正文直接矛盾的绝对化结论

**定位：**`img/media-corn-rice-tween.svg:63` 把一项形态特征写成白念珠菌独有；`:40` 还把组合表现写成确定的种级结论。与此相对，`data/differential.js:1108`～`:1109` 明确记录了都柏林念珠菌与白念珠菌共享相关表型。

**为什么重要：**这已经能够证明图与软件自身正文不一致，无需靠主观印象判断。图里的“身份证”“其他都没有”等口诀式绝对化表达容易被记成鉴定定论。

**建议：**把这一图列入专业内容优先复核清单；回源后统一图与正文，区分“提示线索”和“最终确认”。同时检索图中“即定种”“唯一”“其他不产生”等强断言，逐条核对适用范围。

**边界：**本轮确定的是内部冲突，不把现有正文自动视为已经重新获得权威核验的最终答案；不在这份视觉审查中给出新的实验条件或诊断算法。

## 三、🟡 阅读与维护问题

### Y1. 统一的小字号，成了全套图片的共同负担

**证据：**2,933 / 4,117 个文字元素采用 9.5 字号，占 71.2%；全部 164 张都有这种小字。`css/styles.css:263` 又按容器宽度缩放图像。390 宽手机上，图像内容宽约 356，9.5 字实际约 **7.05 CSS 像素**；320 宽时约 **5.66 CSS 像素**。这是阅读负担，不把某个推荐字号宣称为 WCAG 法定门槛。

**建议：**图内只放对象、核心短标签和必要对照；依据、例外、长解释放图下可换行正文。核心标签以正常手机显示时约 12–14 CSS 像素作为设计目标，再据此反推排版，不先塞满画布再缩小。

**验收：**390 宽正常页面上，不先打开灯箱也能辨认主要差别；详细文字可使用网页的字号、复制、搜索与读屏能力。

### Y2. 放大查看既可能裁切，也可能根本没明显放大

**证据：**`js/app/detail.js:23`～`:26` 自动旋转横图；`css/styles.css:249`～`:251` 按 `92vw` 定高，却没有同时约束旋转后的另一边。

- 全量实测：768×1024 平板上，**111 / 164 张**首次放大后超出视口。
- 例如革兰染色图，实际上边界约 −53.2、下边界 1077.2，而屏幕高度是 1024。
- 390×844 手机未发现弹窗图越界，但有 **7 张**较高/近方形总览不旋转，图宽仍只有 358；和原页面宽度基本一样，“放大查看”实际上主要是换了背景。

**建议：**默认“整图适合屏幕”，提供继续放大、拖动、复位；旋转改为用户可选择。当前“点击任意处关闭”（`js/app/detail.js:33`）也应收敛为点击遮罩或关闭按钮，以免以后拖图时误关。

**验收：**所有图在手机和平板首次打开完整可见；密集图确实能够继续放大阅读，不只是改变方向。

### Y3. 小字颜色偏淡；深色模式不宜简单反色

**定位：**例如 `img/genetics-hgt.svg:13`～`:14` 的分类标签，以及 `img/biochem-assimilation.svg:27`～`:28` 的灰色小字。

| 前景 / 背景 | 对比度 |
|---|---:|
| `#6b7684` / `#eef1f5` | 4.07:1 |
| `#8c96a2` / `#f7f8f9` | 2.82:1 |
| `#2f8f83` / `#e8f3ef` | 3.44:1 |
| 可复用深灰 `#5c6672` / `#eef1f5` | 5.15:1 |

**建议：**提高文字对比度，保留对象本身有教学含义的颜色；颜色区分同时配文字或符号。`css/styles.css:819` 只能改外部图片底色，不能改 SVG 内部白底；夜间白色插图可作为明确的浅色画布保留，不要用全图反色/滤镜去“适配”，避免把示意颜色一起改错。

**验收：**普通阅读文字以至少 4.5:1 为目标，按实际背景计算；这份报告不是整站 WCAG 合规认证。参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)。

### Y4. 图注不够具体，灯箱键盘焦点会进入背景

**定位：**`js/app/router.js:37` 及 `:53`～`:60` 生成模块级通用图名；`js/app/detail.js:400`～`:401` 将其同时用作图片替代文字和图注。仅写“试验示意图”，无法表达这是哪项试验、当前词条为什么共用它。

`js/app/detail.js:31`～`:41` 打开灯箱未转移或限制焦点；`:9`～`:14` 关闭未恢复焦点。本轮真实浏览器中，打开 TSI 配图后按 Tab，焦点进入背景正文的 TSI 链接，而不是留在弹窗；弹窗也未声明 `aria-modal`。

**建议：**为图片建立轻量元数据：具体图名、简短解释、适用条目、来源、复核状态。外部 `img` 不应仅依赖 SVG 内部 `title/desc`；复杂图要有可见文字解释。打开灯箱聚焦关闭按钮，阻止焦点进入背景，关闭后回到原图。

**验收：**单独读图注能知道图在说明什么；仅用键盘可进入和退出放大图。未进行完整 VoiceOver 实测，不声称覆盖所有辅助技术。

### Y5. 应补“语义与真实渲染”检查，而不是继续堆纯文字 lint

**证据：**`node tools/release-check.mjs` 本轮全部通过：内容自检、164 张 SVG lint、缓存清单、124 项测试及空白字符检查均绿。但 R1～R4 仍然存在。

具体原因包括：

- `tools/lint-svg.mjs:74`～`:93` 遇到 `tspan` 时只处理其内容，漏掉父文本及后续尾文。
- `tools/lint-svg.mjs:73` 没有完整继承祖先字号和锚点；`:33`～`:36`、`:68` 跳过部分变换。
- 只比较文字，不知道后绘制的色块覆盖了结构；文件存在测试也不知道图片和条目主题是否相符。
- 图内重复写正文知识，形成第二份手工维护源。`img/landing-glossary.svg:60` 本身已有“避免双源失同步”的原则，其他图也应遵循。

**建议：**保留快速 lint，补浏览器全量边界检测、几个真实遮挡回归样例、主题映射断言和手机/平板灯箱测试。图内数值和适用范围关联到已核验的知识条目，来源、版本和复核状态放在图外统一维护。

**验收：**新检查至少能抓住本轮确定缺陷。不要把启发式检测的候选数量直接当作确定缺陷数量；也不要为了测试绿而删除检测。

### 2. 一图两层：先看懂，再深入

推荐页面结构：**一句核心问题 → 主图 → 一句结论 → 可展开的解释与限制 → 来源**。

图片正常状态只承担“看出关系和差别”。需要精读的内容留在网页中，而不是压进页脚。这能同时解决小字、裁切、手机适配、文字搜索和读屏问题，比给所有图片统一加字号更稳妥。

### 3. 示意图与真实照片分工，而不是互相替代

示意图适合凸显结构和比较；真实图谱适合展示质感、形态变异和不典型外观。可以在已有授权/来源清楚的照片基础上做“示意 / 实图”切换。不要给虚构的示意比例添加看似精确的尺度，也不要把颜色示意当作跨产品、跨拍摄环境的固定标准。

### 4. 把图片用来学习，而不只用来浏览

在基础版式修好后，可增加轻量“隐藏标签 → 自己辨认 → 显示解释”模式，利用同一套结构图做复习。先选少量形态图试点；涉及临床判读的内容不能因为做成题目而省略适用范围和限制。

### 5. 优先改影响大的图，而不是随机挑漂亮的重绘

当前机制细胞壁图被 39 个条目复用、蛋白质图 22 个、糖类面板 15 个；这些是影响面指标，不代表它们全部有错误。结构术语图被 11 个词条共用且已经存在遮挡，应比普通装饰性调整优先。

## 五、实施顺序与验收

1. **先止错：**撤下明确错配图；处理被盖住的结构、明显文字截断和图文知识冲突。
2. **修共用显示组件：**灯箱整图适配、继续放大、手动旋转、焦点管理。一个组件修好会惠及所有图片。
3. **做少量样板：**选结构图、密集生化图、培养基图、机制图、模块总览各一张，验证“主图少字＋图下说明”，不要一次性重绘全部图片。
4. **按影响面迁移：**先高复用和高阅读负担图，再逐类推进；医学文字改动单独回源，不混在美化提交里。
5. **发布前：**改图后同步图片缓存清单并更新资源版本，跑发布检查；再按本报告复现路径实测，不以全绿代替视觉验收。

### 不建议做的事

- 为了“风格统一”一键重绘 164 张，丢失已经核验的图形和文字。
- 继续添加渐变、阴影、动画，却不减少阅读负担。
- 把全部 SVG 转为 PNG，或将文字转路径来掩盖文字检查问题。
- 以“每页必须有图”为目标牺牲主题准确性。
- 把单机浏览器检查或视觉模型意见包装成医学认证、跨设备完全无误。
