### 🔴 严重问题（R1–R2）

#### R1 · `js/app/helpers.js:63` + `js/app/search.js:120` — 真实 UI 全文搜索漏索引微生物「形态」「生化反应」「相似菌与鉴别」
- **位置**：`js/app/helpers.js:63-77`、`js/app/search.js:120`、`js/core.js:196-200`
- **原因**：`Core.createSearchIndex(db)` 在构建微生物搜索文档时，读取 `db.morphology[id]`、`db.biochem[id]`、`db.differential[id]` 拼入全文索引（单元测试 `tests/core.test.js:85-98` 用手工传入的 mock `db` 通过了测试）。但浏览器端真实调用的 `NS.db()`（`js/app/helpers.js:63`）只返回了 12 个模块数组，**未挂载 `morphology`、`biochem`、`differential` 三个字典**。导致用户在顶栏搜索框输入「葡萄串状」「双圈溶血」「卫星现象」等表型或鉴别词时，若条目主小节未重复出现该词，真实 UI 搜索完全无法命中对应菌种。
- **修法**：在 `js/app/helpers.js` 的 `db()` 中通过 `Object.defineProperties` 将 `morphology`、`biochem`、`differential` 挂载为**不可枚举属性**（既让 `Core.createSearchIndex(NS.db())` 完整索引形态、生化、鉴别文本，又保证 `Object.entries(NS.db())` / `Object.keys(NS.db())` 仍严格只枚举 12 个模块数组，不破坏 SVG 与模块遍历逻辑）；并在 `tests/search-ui.test.js` 新增 UI 级回归测试。

#### R2 · `js/validate.js:5-15` + `tools/audit-content.mjs:50-59` + `tests/data-integrity.test.js:46-55` + `tests/tools.test.js:31-40` — 数据自检与测试漏检 4 个模块
- **位置**：`js/validate.js:5-15`、`tools/audit-content.mjs:40-59`、`tests/data-integrity.test.js:46-55, 211-219`、`tests/tools.test.js:31-40`、`tests/view.test.js:36-46`
- **原因**：后续新增的 `virulence`（致病因素）、`genetics`（遗传与变异）、`glossary`（术语）、`qc-strains`（质控菌株）未同步补齐到 `js/validate.js`、`tools/audit-content.mjs` 及 `tests/data-integrity.test.js` 的 `Core.validateData(db, categories)` 入参中，导致这 4 个模块的分类合法性、悬空关联、跨模块重复 ID 以及总览图存在性处于自检盲区。
- **修法**：在 `js/validate.js`、`tools/audit-content.mjs`、`tests/data-integrity.test.js`、`tests/tools.test.js`、`tests/view.test.js` 中补齐全部 12 个模块与全部 15 张模块总览 SVG 校验。

### 🟡 中等问题（Y1–Y7）

#### Y1 · `css/styles.css:385-396, 639-656` — 4 个模块缺失语义色（`.chip-<module>` / `.tag-<module>`）且亮色模式选择器重复声明

  2. 亮色模式下 `.chip-<module>`（385 行）与 `.tag-<module>`（641 行）分两处重复写了两遍完全相同的色值。
- **修法**：
  1. 合并亮色模式 `.chip-<module>, .tag-<module>` 选择器，消除重复声明。
  2. 为缺失的 4 个模块增补符合「知微实验室纸本」低饱和调性的专属语义色（亮色模式与暗色模式均逐一校验对 `--surface`、`--bg`、`--line-2`、`--accent-weak` 四种背景的 WCAG 对比度，亮色达 **5.24:1～6.88:1**，暗色达 **5.66:1～8.58:1**）：
     - `virulence`（致病因素）：暗绯棕 `#8c4a4a` / 暗色 `#d99a9a`
     - `genetics`（遗传与变异）：靛蓝 `#4a588c` / 暗色 `#9aa8e0`
     - `glossary`（术语）：石板蓝灰 `#526373` / 暗色 `#a8b8c8`
     - `qc-strains`（质控菌株）：深松石绿 `#2f6b5e` / 暗色 `#85c4b4`
  3. 在 `tests/data-integrity.test.js` 新增断言，强制要求 `Core.MODULE_KEYS` 中每个模块都在 `css/styles.css` 中具备 `.chip-<module>` 与 `.tag-<module>` 样式。

#### Y2 · `index.html:29-54` + `js/core.js:9` — 顶栏模块与快捷工具排列顺序未按检验工作流分组
- **位置**：`index.html:29-54`、`js/core.js:9`
- **原因**：
  1. 原模块顺序（`微生物 → 抗微生物药 → 耐药 → 致病因素 → 遗传与变异 → 术语 → 检测卡 → 试验 → 培养基 → 染色 → 生化反应 → 质控菌株`）是按历史开发批次追加的，导致检验科日常最常用的「染色、培养基、生化反应、试验、检测卡」被压在第二行末尾，而理论通识模块插在中间。
  2. 快捷工具双列网格中，`生化鉴定` 与 `标本流程`、`药敏卡对比` 与 `异常药敏` 分散在不同行，视觉配对松散。
  3. `Core.MODULE_KEYS` 与 `index.html` 的标签顺序维护两套不一致的次序。
- **修法**：
  1. 统一 `Core.MODULE_KEYS` 与 `index.html` 顶栏模块顺序，按**「病原与表型鉴定 → 药敏与质控 → 机制与理论通识」**的检验与教学逻辑重排：
     - 第一梯队（病原与表型鉴定）：`微生物分类` → `染色` → `培养基` → `生化反应` → `试验` → `检测卡`
     - 第二梯队（药敏与质控）：`抗微生物药` → `耐药因素` → `质控菌株`
     - 第三梯队（机制与理论通识）：`致病因素` → `遗传与变异` → `术语`
  2. 快捷工具面板按双列 4 组功能对重排：
     - 第 1 行（折点与耐药基准）：`折点判读` ｜ `天然耐药`
     - 第 2 行（药敏审核与卡片）：`异常药敏` ｜ `药敏卡对比`
     - 第 3 行（检验操作与鉴定）：`标本流程` ｜ `生化鉴定`
     - 第 4 行（菌名检索与名录）：`菌名速查` ｜ `常见菌菌名速查`

#### Y3 · `js/app/detail.js:492-706` — 微生物详情页「表型鉴定」与「药敏/治疗」板块交错穿插
- **位置**：`js/app/detail.js:492-706`
- **原因**：原 `buildDetail(vm)` 的渲染顺序为：`小节 → 天然耐药 → 治疗要点 → 培养与镜下形态 → 真实形态图 → 药敏折点 → ECV → 分型鉴定表 → 相似菌与鉴别 → 生化反应`。阅读时在「药敏/治疗」与「形态/生化/鉴别」之间来回横跳两次，不符合临床微生物室「先看涂片/菌落/生化/鉴别定菌种，再看天然耐药/折点/ECV/治疗发报告」的思维路径。
- **修法**：重排 `buildDetail(vm)` 的顶层内容块顺序（`buildDetailToc` 自动读取渲染后的顶层块，因此页内「本页速览」目录同步更新）：
  1. **概览与核心小节**：`机制图` → `小节`
  2. **第一板块（表型与培养鉴定）**：`培养与镜下形态` → `真实形态图` → `生化反应` → `分型鉴定表` → `相似菌与鉴别`
  3. **第二板块（药敏判读、耐药与临床治疗）**：`CLSI 质控/参考范围` → `天然耐药` → `药敏折点` → `流行病学界值 (ECV)` → `治疗要点` → `包含药物`
  4. **第三板块（知识图谱与外链）**：`关联` → `综述 / 参考`

#### Y4 · `js/app/detail.js:9-62` — 示意图放大弹窗（`openImageZoom` / `closeImageZoom`）缺少无障碍焦点管理
- **位置**：`js/app/detail.js:9-62`
- **原因**：点击或按回车打开 `.zoom-overlay`（`role="dialog"`）时，焦点仍留在背景页元素上；按 `Escape` 或点击关闭后，焦点也未恢复到原触发图片，且弹窗未标注 `aria-modal="true"`（此前 `docs/审核/SVG配色与风格复审-20261003.md` 亦指出该待办）。
- **修法**：在 `openImageZoom` 打开前记录 `document.activeElement`，为 `.zoom-overlay` 补齐 `aria-modal="true"`，挂载后自动聚焦 `.zoom-close` 按钮；在 `closeImageZoom` 卸载浮层后将焦点无滚动恢复（`focus({ preventScroll: true })`）至原触发控件，并在 `tests/detail-navigation.test.js` 补充焦点往返测试。

#### Y5 · `js/app/helpers.js:63` + `js/app/router.js:33-36` + `js/app/sidebar.js:131` + `js/app/landing.js:54` — 每次路由切换重复构建全库索引并全表扫描反向关联
- **位置**：`js/app/helpers.js:63-77`、`js/app/router.js:33-36`、`js/app/sidebar.js:131`、`js/app/landing.js:54`
- **原因**：
  1. `NS.db()` 每次调用都新建对象，且 `router.js:33`、`sidebar.js:131`、`landing.js:54` 在每次路由切换时各自调用 `Core.buildIndex(db())`，单次页面跳转重复遍历全库构建 2～3 次索引。
  2. `Core.getRelations(id, db, index, reverseIndex)` 支持传入预构建的 `reverseIndex`（O(1) 查反向关联），但 `router.js:36` 未传第 4 个参数，导致每次点开任意条目详情都要全表扫描 1,300+ 条目与全部关联数组。
- **修法**：在 `js/app/helpers.js` 中缓存 `db()`、`dbIndex()`、`dbReverseIndex()`（并在底层 `window.DB` 数组引用变化时自动失效重建，兼容单元测试动态替换 `window.DB`）；`router.js`、`sidebar.js`、`landing.js` 统一复用 `NS.dbIndex()` 与 `NS.dbReverseIndex()`。

#### Y6 · `js/app/detail.js:240-267` — `richInline` 正文站内链接渲染在每步循环扫描全量词典
- **位置**：`js/app/detail.js:240-267`
- **原因**：`linkDict()` 包含约 1,500 个菌名、药名、缩写与别名键。`richInline(text)` 在 `while (rest.length)` 的每一步切分循环中都对全部 1,500 个键执行 `rest.indexOf(k)`，一段含 8 个链接的正文需执行约 12,000 次子串搜索。
- **修法**：在进入 `while` 循环前，先对 `rest` 预筛一次命中的候选键列表 `activeKeys`（通常仅 0～8 个），若无命中直接返回单文本节点；`while` 循环内部仅遍历 `activeKeys`，将多链接段落的子串匹配次数降低约 90%。

#### Y7 · `js/app/bp-table.js:56-81` + `js/app/detail.js:589-616` + `js/app/helpers.js:179-424` — 折点表 DOM 构建重复 & 生化别名表含 35 个重复键
- **位置**：`js/app/bp-table.js:56-81`、`js/app/detail.js:589-616`、`js/app/helpers.js:179-424`
- **原因**：
  1. `detail.js` 渲染微生物详情页折点表与 `bp-table.js` 渲染折点判读工具表几乎完全相同（仅 `d.MIC` 合并串与 `d.MIC_S/I/R` 原始字段的读取方式差一行），却维护了两份 25 行的表格构建代码。
  2. `js/app/helpers.js` 的 `biochemTestIdByName()` 别名映射对象字面量因历史多次追加，存在 **35 个完全重复的键**（如 `'42℃生长'`、`'6.5% NaCl'`、`'Optochin'`、`'触酶'`、`'氧化酶'`、`'脲酶'`、`'七叶苷'` 等各定义了 2～3 次）且缩进混乱。
- **修法**：
  1. 在 `js/app/bp-table.js` 抽离通用函数 `buildBpTableScroll(drugs, eu)`（兼容 `d.MIC` 与 `d.MIC_S/I/R`），供 `bp-table.js` 与 `detail.js` 共用。
  2. 清理 `js/app/helpers.js` 中全部 35 个重复键并按生化试验分组规整排版。

### 🟢 轻微问题（G1–G3）

#### G1 · `index.html:27-55` + `css/styles.css:42` — 死 DOM 节点与重复无障碍地标
- **位置**：`index.html:27-55`、`css/styles.css:42`
- **原因**：`index.html` 中保留了两个 `<div class="nav-board-title">`，而在 `css/styles.css:42` 中直接设置了 `.nav-board-title { display: none; }`；同时外层 `<div class="nav-board" aria-label="...">` 与内层 `<nav aria-label="...">` 使用了完全相同的 `aria-label`，对屏幕阅读器造成冗余播报。
- **修法**：移除 `index.html` 中两个无用的 `.nav-board-title` 节点及外层 `div.nav-board` 上的重复 `aria-label`，同步删除 `css/styles.css` 中的 `.nav-board-title` 死规则。

#### G2 · `css/styles.css:86, 152-153, 301, 439-444` — CSS 历史残留选择器与未定义变量兜底
- **位置**：`css/styles.css:86`、`css/styles.css:152-153`、`css/styles.css:301`、`css/styles.css:439-444`
- **原因**：
  1. `.cat-genus-link::before` 使用了未定义的 `var(--line-3, #bbb)`，导致暗色模式下回落到刺眼的亮灰 `#bbb`。
  2. `.lw-nav-item` 使用了旧版亮绿兜底 `var(--accent, #0a6)` 与 `var(--line, #eee)`。
  3. `.photo-dots` 在 291 行与 301 行重复定义。
  4. `.bp-tier-A/B/C/U/O` 为 CLSI 旧版 A/B/C/U 分组残留样式，全库已全面改用 Ed36 Tier 1–4（`.bp-tier-1`～`.bp-tier-4`），无任何代码引用。
- **修法**：将 `--line-3` 替换为主题变量 `var(--muted)`，移除旧 `#0a6`/`#eee` 兜底，合并 `.photo-dots`，删除无用的 `.bp-tier-A/B/C/U/O` 规则。

#### G3 · `js/app/*.js` 尾部 `Object.assign(NS, ...)` — 导出原始值快照与私有缓存死属性
- **位置**：`js/app/helpers.js:680`、`js/app/sidebar.js:187`、`js/app/compare.js:265`、`js/app/detail.js:735`、`js/app/tools-info.js:399`、`js/app/tools-drug.js:523`
- **原因**：从单文件 `js/app.js` 拆分为 `js/app/*.js` 时，各文件尾部的 `Object.assign(NS, ...)` 把模块内部的可变原始值状态（如 `_abxNameMap`、`_favCache`、`_linkDict`、`_zoomEl`、`mnFilter`、`astFilter`、`bpDrugFilter` 等）在 IIFE 初始化瞬间按值拷贝到了 `window.AppNS` 上。由于 JS 对象属性赋值是值拷贝，后续函数内部修改闭包变量时，`NS.xxx` 永远停留在初始 `null` 或 `''`，既无外部读取又容易误导维护者。
- **修法**：清理全部 6 个文件中无外部引用的原始值快照导出，仅保留真实跨文件调用的函数与常量。
