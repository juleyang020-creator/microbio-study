# 代码结构优化与文档更新报告（2026-09-05）

任务：优化软件代码结构，更新描述性文件（README / CHANGELOG）与限制性文件（.gitignore）。

## 一、代码结构

### 1. `js/app.js`（2830 行单文件）拆分为 `js/app/` 九个文件

拆分前 `js/app.js` 为单个 IIFE、154 KB、332 个函数，是全仓库最大的维护痛点。

拆分方式：按文件内既有的功能分节机械切割，**逐字节保留原代码**（脚本比对确认九个文件体与原文
4–2829 行完全一致，唯一例外见下），不引入打包器 / ES module，保持 `file://` 双击可用：

| 文件 | 行数 | 职责 |
|---|---|---|
| `helpers.js` | 675 | 基础原语：`el/fill/sg`、路由解析、名称→id 词典、折点分层徽标、滚动渐隐、`APP_VERSION` 兜底 |
| `sidebar.js` | 188 | 分类树侧栏、收藏夹 / 最近浏览（localStorage） |
| `search.js` | 61 | 搜索结果与命中高亮 |
| `compare.js` | 266 | 生化鉴定（对比 + 结果查菌）、药敏卡对比 |
| `bp-table.js` | 83 | CLSI/EUCAST 折点表构建（详情页与折点工具共用，拆出以解循环依赖） |
| `tools-info.js` | 334 | 关于页 / 标本流程 / 菌名速查 |
| `detail.js` | 595 | 详情页富渲染（示意图放大、照片轮播、站内链接词典） |
| `tools-drug.js` | 524 | 天然耐药 / 折点判读 / 异常药敏 |
| `router.js` | 162 | 路由分发 + `init()` 启动（最后加载） |

跨文件共享机制：各文件为独立 IIFE，定义在末尾 `Object.assign(NS, {...})` 导出到
`window.AppNS`，依赖在开头 `var x = NS.x` 导入；`<script>` 加载顺序即依赖顺序。

拆分中由脚本静态分析发现并处理的两处结构问题：

1. **真循环依赖**：详情页（`buildDetail`）调用折点表构建器，而异常药敏工具（`astLine`）调用
   详情区的 `richInline`。解法：把折点表构建器抽为独立的 `bp-table.js`，两边都向它依赖，
   循环消除。
2. **`detail → router` 反向引用**：详情页收藏按钮回调需重渲染。该调用点改写为
   `NS.renderRoute()`（运行时查表，不受加载顺序限制）——这是拆分全过程中对原代码的**唯一**
   一处内容改动（`js/app/detail.js:322`）。
