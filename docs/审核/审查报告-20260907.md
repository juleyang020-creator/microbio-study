# 知微 UI、搜索与局部重构审查报告

日期：2026-09-07  
上线资源版本：`20260907-71`  
状态：**已提交并通过 PR #106 合并 main，GitHub Pages 部署成功，线上实测通过。**

## 结论

本轮保留原有静态 PWA 架构与医学内容，集中调整导航、首页、搜索结果、长页阅读和手机交互。没有引入框架、打包器或应用运行依赖，仍支持双击 `index.html` 使用。

汇总整改项：🔴 **0** 项阻断级；🟡 **7** 项应调整；🟢 **2** 项工程优化。下列整改均已在本地完成。迭代复审暴露的交互边界问题也已修复并加入回归检查。

## 一、可直接感受到的变化

- **导航**：搜索获得独立位置；知识模块保留直接入口，快捷工具收纳到“工具”菜单，减少手机顶部常驻占位。
- **首页**：增加模块标题、真实条目数、分类卡片、直接条目链接和继续阅读。原有总览图保留在分类入口之后，未删除图片。
- **搜索**：显示结果数、模块筛选和命中上下文；每批显示 40 条，可继续加载。精确名称和确定别名优先于正文提及；多个关键词按“同时匹配”处理。
- **快捷操作**：`/` 或 `Ctrl/⌘ K` 聚焦搜索；上下方向键在结果间移动；`Escape` 退出搜索。中文输入法尚未确认的拼音不触发搜索。
- **返回恢复**：搜索条件和模块保存在地址中；打开详情再返回，可恢复查询。每条搜索记录独立保存退出位置，刷新后仍有效。
- **详情阅读**：长页增加“本页速览”，点击即可跳到对应内容并移动键盘焦点；既有警示、正文和专用分型表跳转保留。
- **声明**：底部始终显示“仅供学习参考 · 不构成诊疗依据”；详细声明可展开，避免全文常驻占用手机阅读区。

## 三、分级整改记录

以下定位指向本轮完成后的代码。

### 🟡 1. 顶部与页脚挤占手机正文

- **定位**：`css/styles.css:36`、`css/styles.css:807`、`index.html:70`。
- **原因**：两个常驻导航面板加完整页脚声明，在手机上占用较多空间；正文与导航的视觉权重也过于接近。
- **修法与结果**：导航分层、工具菜单按需展开、页脚保留醒目的简明警示并支持展开全文；使用动态视口高度。实测数值见上表。

### 🟡 2. 模块首页缺少可操作入口

- **定位**：`js/app/landing.js:28`、`css/styles.css:682`、`js/app/sidebar.js:83`。
- **原因**：原首页主要展示窄幅总览图，未选条目时只提示“选择左侧”；手机侧栏隐藏，用户不容易继续操作。
- **修法与结果**：从现有分类树和条目生成标题、数量、分类卡片与有效链接；直接浏览目录、定位分类，保留原图。最近浏览入口仅从本地已有历史记录生成。

### 🟡 3. 搜索结果缺少范围反馈，名称落点不够可靠

- **定位**：`js/app/search.js:33`、`js/core.js:328`、`js/core.js:20`、`js/core.js:90`。
- **原因**：旧结果没有数量和模块筛选；名字完全匹配与正文提及未充分区分；常用中文简称“金葡”缺少确定名称扩展。另检查到对象原型键被误当别名的异常路径。
- **修法与结果**：增加真实数量、模块筛选、分批呈现；精确名称、精确别名优先；别名只读取词典自身属性，保留英文普通词子串查询但避免短缩写误命中其他单词内部。“金葡”“金葡菌”优先指向金黄色葡萄球菌，不推断菌株表型或耐药性。
- **简称依据**：[东莞市疾控公开释名](https://dghb.dg.gov.cn/zsjg/dzsjbyfkzzx/jkzt/wsjcjy/wswjy/content/post_499224.html)使用“Staphylococcus aureus，简称金葡菌”。本轮仅使用名称释义，未录入该文的检测操作内容。

### 🟡 4. 搜索不是可恢复页面，输入与路由存在时序风险

- **定位**：`js/app/search.js:94`、`js/app/search.js:134`、`js/app/search.js:151`、`js/app/navigation.js:28`。
- **原因**：旧搜索只是替换正文，浏览器返回不能恢复查询；待执行的防抖可能在用户切换目标后覆盖页面。新增状态功能的复审还发现退出位置不能保存在单个共享变量中。
- **修法与结果**：使用专门搜索路由保存查询和模块；首次搜索新增一个历史节点，连续输入只替换此节点；来源保存在每条历史记录的 `history.state`。中文组合输入结束后才查询；内部链接统一取消待执行搜索，同地址点击也正确处理。

### 🟡 5. 手机目录需要完整的键盘与定位支持

- **定位**：`js/app/navigation.js:10`、`js/app/navigation.js:28`、`js/app/landing.js:28`、`css/styles.css:728`。
- **原因**：仅把抽屉移出屏幕不会阻止键盘进入；固定关闭栏可能盖住跳转后的分类标题。复审发现视觉顺序与 DOM 顺序不一致时，仅处理首尾焦点会漏掉 Tab 跳出。
- **修法与结果**：关闭时用 `inert` 隔离目录，打开时隔离背后正文并显示关闭按钮；显式循环抽屉焦点；分类按顶部定位并预留固定栏高度。重复点击当前工具也会关闭菜单。

### 🟡 6. 详情长页查找小节需要反复滚动

- **定位**：`js/app/detail.js:361`、`css/styles.css:697`。
- **原因**：内容持续扩充后，形态、正文、表格和来源分散在较长页面中，缺少统一小节入口。
- **修法与结果**：从实际生成的顶层内容块提取速览目录，不维护第二份医学内容清单；至少三个有效内容块才显示。跳转不改 hash，保证不干扰路由和返回历史。生物安全警示仍位于速览之前。

### 🟡 7. 菌名速查在平板宽度下发生内部横向溢出

- **定位**：`css/styles.css:129`。
- **原因**：同一行的中文名、拉丁名与标记共同撑开格子；900 px 视口下实际正文滚动容器溢出 18 px，文档整体宽度检查却不会报错。
- **修法与结果**：条目允许换行、网格使用可收缩的最小宽度，长名称可断行。最终视口矩阵内无正文横向溢出。

### 🟢 8. 搜索改用一次构建、重复查询的索引

- **定位**：`js/core.js:266`、`js/core.js:313`、`js/app/search.js:120`。
- **原因**：数据虽然静态，应用的 `db()` 每次返回新包装对象；只按对象缓存并不能保证 UI 连续查询复用索引。
- **修法与结果**：搜索控制器首次使用时创建索引，后续查询复用；核心函数仍可独立 Node 测试，兼容原 `searchEntries` 接口。归一规则折叠全角 ASCII 与常见空白，但不改写上标等专业符号，显示片段保持原文。
- **实测**：现有 1,314 个可搜索条目，固定查询批次每批 500 次、重复 5 轮，中位耗时从 **550.55 ms → 143.55 ms**，约 **3.84 倍**吞吐提升。首次建索引约 **41.44 ms**。这是本机纯搜索函数基准，不代表整个页面快 3.84 倍，也不代表所有设备。
- [原始基准记录](ui-20260907/search-benchmark.json)

### 🟢 9. 做职责拆分，而非更换框架

- **定位**：`js/app/router.js:6`、`js/app/navigation.js:28`、`js/app/landing.js:28`、`index.html:130`、`sw.js:9`。
- **原因**：导航事件、首页构建、搜索输入混在路由文件中，容易出现同路由点击未清理状态的遗漏；但当前纯静态部署仍有价值，没有证据证明需要引入框架重写。
- **修法与结果**：拆出导航控制与首页构建，搜索状态由搜索模块负责；路由文件从原 163 行收敛到 81 行。新增脚本已按依赖顺序加载并加入离线预缓存。没有增加应用依赖，没有改变数据加载方式。
